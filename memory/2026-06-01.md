## Stable Yogi 2602 ZiT checkpoint + exact-repro detour

- Added `Zimage Turbo NSFW by Stable Yogi` `2602-NSFW-BF16` Z-Image Turbo
  checkpoint: control `2646e14`, model archive `3ca8c53`. Reference Civitai
  image `120285584` has no embedded ComfyUI workflow (param-only); reconstructed
  as a plain-node text-to-image workflow. Trigger `99bsy99`.
- Key finding: the reference image and the author's official preview reel were
  generated with **Forge Neo** (a Forge/A1111-family WebUI), identified via the
  `Version: neo` metadata field — not ComfyUI and not SwarmUI. Consequence:
  exact pixel reproduction from a ComfyUI graph is not achievable, and matching
  the image's parameters across engines is futile. The committed BSY
  sidecar/`.txt` still describe these as "SwarmUI-style"; that label is
  inaccurate (it is Forge Neo) and should be corrected if those docs are touched.
- Exact-repro attempts with ~zero visual effect, both rolled back: fp8 text
  encoder swap (`qwen_3_4b_fp8_mixed`) and a discard-penultimate-sigma
  custom-sampler path (RES4LYF `bong_tangent` sigmas + core `SplitSigmas` +
  `Sigmas Concat`). Active workflow stays plain `KSampler` +
  `qwen_3_4b.safetensors`. Note: the committed workflow's `bong_tangent`
  scheduler is RES4LYF-provided, so the workflow implicitly requires RES4LYF.
- The fp8 encoder is kept as a documented standalone archive asset for future
  use: model archive `76c8854` (`text_encoders/qwen_3_4b_fp8_mixed.md/.html`,
  weight gitignored, `applies_to` the Z-Image Turbo family + the BSY checkpoint).
